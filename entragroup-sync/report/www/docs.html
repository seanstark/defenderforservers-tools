How the Azure Function worker discovers Azure Arc servers, correlates Defender for Endpoint (MDE) telemetry, and manages Entra ID group membership.

Scoped Discovery & Queueing

  • Inventory (NCRONTAB timer) and ArcEvent (Event Grid when MDE.Windows or MDE.Linux extension completes with provisioningState == "Succeeded") validate Management Group, Subscription, and Resource Group scope.
  • Azure Resource Graph discovers Microsoft.HybridCompute/machines, non-AKS Azure Native VMs, and VMSS instances.
  • Service Bus queue decouples discovery spikes from per-machine correlation with 10-delivery dead-letter protection.

Hunting-Only MDE & Per-Account Cloud account Group Sync

  • All MDE telemetry (DeviceInfo, DeviceNetworkInfo, scid-2010 AV mode, tags, MachineGroup) comes via Graph /security/runHuntingQuery.
  • Routes each correlated Windows or Linux machine to its per-account Cloud account Entra security group (AWS by AccountId tag, GCP by ProjectId tag, or Azure by SubscriptionName with AWS & GCP excluded).
  • Audit mode records WouldAdd; Enforce mode writes mutation intent first, adds directory object ID, and verifies read-back.

Isolated Role-Based Reporting

  • Atomic Azure Table batch commits current state and h_ history snapshots plus system/inventory and log_ execution logs.
  • Separate Report Function App has Storage Table Data Reader and Sender only on the dedicated inventory-sync queue. Easy Auth + Report.Reader in the configured tenant protects both viewing the report and starting inventory.
  • The diagram shows discovery and reporting; the separate manual control path sends inventory requests to the worker through inventory-sync. Timer and manual runs share an atomic job claim. Deploy infrastructure and both packages; ZIP upload alone does not provision this control path.
  • Inventory completion means discovery, group preparation, and machine queueing finished; device processing may continue. Missing completion is marked Interrupted after 15 minutes. Keep the worker function timeout at most 10 minutes for safe claim recovery; check worker logs and the inventory queue's dead-letter messages for stalled requests.
  • Interactive Defender-style portal provides KPI filters, hover popovers, context drawer, Function App telemetry, and docs.
3-Tier Microsoft Entra ID device correlation chain

How the Machine Sync Worker resolves an MDE-onboarded server to its Microsoft Entra ID device object across Entra-joined, Machine Configuration-enrolled, and MicrosoftSense-managed servers:

Priority Correlation Method (Correlation method column) How It Works When It Is Used
Tier 1 MDE AadDeviceId (MdeAadDeviceId) Reads AadDeviceId from MDE Advanced Hunting (DeviceInfo) and queries GET /v1.0/devices?$filter=deviceId eq '{AadDeviceId}'. Primary method for Microsoft Entra joined or hybrid joined servers where MDE directly reports AadDeviceId.
Tier 2 Machine Configuration (intuneDeviceId) (GuestConfigurationIntuneDeviceId) Reads intuneDeviceId=<guid> from GuestConfigurationResources (entraiddeviceid on Windows reading HKLM\SOFTWARE\Microsoft\SenseCM\EnrollmentPayload; entraiddeviceidlinux on Linux reading wdavstate with a fallback to the newest enrollment result in /var/log/microsoft/mdatp/microsoft_defender_enterprise_sensecm.log) and queries GET /v1.0/devices?$filter=deviceId eq '{intuneDeviceId}'. Used when AadDeviceId is empty in MDE (workgroup / AWS / GCP / Linux servers enrolled via MDE Security Settings Management) and the Azure Machine Configuration assignment has reported back.
Tier 3 MicrosoftSense (Hostname & OS) (MicrosoftSenseHostnameAndOS) Queries GET /v1.0/devices?$filter=displayName eq '{hostname}' across candidate hostnames (ComputerName, MdeDeviceName, Fqdn, MachineName) and requires a unique match on operatingSystem (Windows / Linux) and managementType == 'MicrosoftSense'. Automatic fallback when AadDeviceId is empty and the Machine Configuration assignment has not yet reported.

Gates 1–2: Scope & ARM State Criteria

  • Supported resource types: Microsoft.HybridCompute/machines, Microsoft.Compute/virtualMachines, Microsoft.ClassicCompute/virtualMachines, and Microsoft.Compute/virtualMachineScaleSets/virtualMachines (excluding Compute.AKS).
  • Scope rule: (Subscription in SYNC_SUBSCRIPTION_IDS OR SYNC_MANAGEMENT_GROUP_IDS) AND (SYNC_RESOURCE_GROUP_NAMES empty OR matching RG).
  • ARM state criteria: Arc properties.status == "Connected"; Azure VM / VMSS PowerState must not be deallocated or stopped (otherwise stops with ArcNotConnected or ArcMissing on HTTP 404).

Gates 3–4: MDE & 3-Tier Entra Identity Correlation

  • MDE DeviceInfo criteria: Latest row per DeviceId over 7 days where AzureResourceId =~ resourceId (or AzureVmId =~ vmId), OnboardingStatus == "Onboarded", MergedToDeviceId == "", and Timestamp >= now() - SYNC_FRESHNESS_HOURS (default 24h).
  • Tier 1 — MDE AadDeviceId (MdeAadDeviceId): Queries GET /v1.0/devices?$filter=deviceId eq '{AadDeviceId}' when MDE reports a valid GUID.
  • Tier 2 — Azure Machine Configuration intuneDeviceId (GuestConfigurationIntuneDeviceId): Joins GuestConfigurationResources (entraiddeviceid on Windows reading HKLM\SOFTWARE\Microsoft\SenseCM\EnrollmentPayload; the entraiddeviceidlinux family on Linux reading wdavstate with a newest-enrollment SenseCM log fallback) to extract intuneDeviceId=<guid> and queries GET /v1.0/devices?$filter=deviceId eq '{intuneDeviceId}'. Linux policy 2.0.0 uses the distinct configuration entraiddeviceidlinux_1.0.2 with package version 1.0.2. Publish the exact built ZIP and update its policy/assignment name, URI, hash, and version; retain legacy assignments and history.
  • Tier 3 — MicrosoftSense Hostname + OS Fallback (MicrosoftSenseHostnameAndOS): Queries GET /v1.0/devices?$filter=displayName eq '{hostname}' across candidate hostnames and matches operatingSystem + managementType == "MicrosoftSense".
  • Event Grid Trigger (ArcEvent): Handles Microsoft.Resources.ResourceWriteSuccess events. For an entraiddeviceid* guestConfigurationAssignment, the worker reads the current resource and queues synchronization only if properties.complianceStatus is Compliant; other or missing statuses are logged and skipped. MDE.Windows / MDE.Linux extension events still require successful provisioning. Scheduled and manual inventory are unchanged. A compliance transition alone does not guarantee a resource-write event.
  • MDE-triggered audit refresh: In Enforce mode, successful MDE extension events also request fresh processing of matching existing Entra-ID Audit assignments. For Linux, the newest version-named configuration is preferred; legacy configurations are refreshed only when no version-named configuration exists. Package hash, version, parameters, and Audit mode are preserved; hidden package URIs are resolved only from hash-matched deployed policies. Requests are deduplicated by event and assignment ID, and pending/uncertain writes are not blindly repeated. Missing assignments require Azure Policy deployment/remediation. The agent reports asynchronously, so request acceptance does not mean the audit has completed. No server commands or assignment deletion/recreation are used.

Gates 5–6: Per-Account Active / Passive Cloud account Group & Flags

  • Global default mode (SYNC_DEFAULT_GROUP_MODE): Defaults to Passive (can be set to Active). Devices are added to their corresponding Passive (or Active) group by default: <Prefix>{Passive|Active}-<AccountId|ProjectId|SubscriptionName>.
  • Counterpart group protection: Queries GET /devices/{objectId}/memberOf. If SYNC_DEFAULT_GROUP_MODE == "Passive" and the device is already in an Active group, it is not added to the Passive group (and vice versa when default is Active).
  • Inventory-first group provisioning (SYNC_ADMIN_UNIT_ID): Scheduled inventory deduplicates discovered cloud-account/OS combinations and prepares missing active/passive pairs before queuing machine correlation. In Enforce mode with auto-creation enabled, groups are created inside the AU through atomic creation reservations. A completed reservation at least 30 minutes old can be conditionally renewed if its recorded group returns HTTP 404; the AU is checked again before recreation. Recent, undated, pending, or uncertain creations remain blocked. Audit mode only reports missing groups. Groups can therefore exist before any device successfully correlates.
  • Shared group IDs: A paginated, generation-checked AU group catalog in the sync table expires after 30 minutes. Workers reuse it instead of independently listing the AU. Expired or incomplete catalogs fall back to Graph; publication errors stop inventory before machine work is queued. Live group eligibility, names, and AU membership are checked before a shared lookup authorizes a membership update. Event-driven machines in new accounts retain guarded on-demand provisioning.
  • Table compliance flags: Flags devices when (1) in an Active group with MDE mode Passive (Should be Active), (2) in a Passive group with MDE mode Active (Should be Active), (3) in multiple groups (all groups shown in Entra ID Group), or (4) in a wrong group where AWS Account ID, GCP Project, or Azure Subscription does not match.
Queries used (Azure Resource Graph & Defender XDR Advanced Hunting)

Azure Resource Graph — Azure Arc & Native Virtual Machine discovery (with properties, tags, subscription name, extensions & Machine Configuration intuneDeviceId)

Discovers Azure Arc machines and non-deallocated, non-AKS Azure Native VMs and joins subscription display names, management groups, installed extensions, and the entraiddeviceid / entraiddeviceidlinux Guest Configuration intuneDeviceId in a single Resource Graph query:

Resources
| extend type = tolower(type)
| where type == 'microsoft.hybridcompute/machines'
    or (
        type in ('microsoft.compute/virtualmachines', 'microsoft.classiccompute/virtualmachines')
        and tostring(properties.extended.instanceView.powerState.displayStatus) !contains 'deallocated'
        and tostring(properties.virtualMachineProfile.extensionProfile) !contains 'Compute.AKS'
    )
| extend machineId = tolower(id)
| join kind=leftouter (
    ResourceContainers
    | where type =~ 'microsoft.resources/subscriptions'
    | extend mgId = tostring(properties.managementGroupAncestorsChain[0].name),
             mgDisplayName = tostring(properties.managementGroupAncestorsChain[0].displayName)
    | project subscriptionId, subscriptionName = name, managementGroup = iff(isempty(mgDisplayName) or mgDisplayName == mgId, mgId, strcat(mgDisplayName, ' (', mgId, ')'))
) on subscriptionId
| join kind=leftouter (
    Resources
    | where type in~ ('microsoft.hybridcompute/machines/extensions', 'microsoft.compute/virtualmachines/extensions')
    | extend machineId = tolower(substring(id, 0, indexof(tolower(id), '/extensions/')))
    | summarize argExtensions = make_list(strcat(name, ' (version: ', tostring(properties.typeHandlerVersion), '; state: ', tostring(properties.provisioningState), ')')) by machineId
) on machineId
| join kind=leftouter (
    GuestConfigurationResources
    | where type =~ 'microsoft.guestconfiguration/guestconfigurationassignments'
    | where tolower(name) startswith 'entraiddeviceid'
    | extend machineId = tolower(substring(id, 0, indexof(tolower(id), '/providers/microsoft.guestconfiguration/')))
    | extend reasonPhrase = tostring(properties.latestAssignmentReport.resources[0].reasons[0].phrase)
    | parse reasonPhrase with * "intuneDeviceId=" gcEntraDeviceId
    | where isnotempty(gcEntraDeviceId)
    | summarize arg_max(tostring(properties.lastComplianceStatusChecked), gcEntraDeviceId) by machineId
    | project machineId, gcEntraDeviceId
) on machineId
| project id, name, type, subscriptionId, subscriptionName, managementGroup, resourceGroup, tags, properties, systemData, argExtensions, gcEntraDeviceId
| order by id asc

Azure Resource Graph — Virtual Machine Scale Set (VMSS) instance discovery (with properties, tags & subscription name)

Joins non-AKS Virtual Machine Scale Sets with running VMSS instances in ComputeResources and subscription names in ResourceContainers:

Resources
| extend type = tolower(type)
| where type == 'microsoft.compute/virtualmachinescalesets'
| extend extensions = tostring(properties.virtualMachineProfile.extensionProfile)
| where extensions !contains 'Compute.AKS'
| extend vmssId = tolower(id), vmssName = name, vmssTags = tags
| project id, vmssName, vmssId, subscriptionId, resourceGroup, vmssTags
| join kind=leftouter (
    ResourceContainers
    | where type =~ 'microsoft.resources/subscriptions'
    | project subscriptionId, subscriptionName = name
) on subscriptionId
| join (ComputeResources
| where type =~ "microsoft.compute/virtualmachinescalesets/virtualmachines"
| extend vmssId = tolower(substring(id, 0, indexof(id, "/virtualMachines/")))
| where tostring(properties.extended.instanceView.powerState.displayStatus) !contains 'deallocated'
) on vmssId
| project id = id1, name = name1, type = type1, subscriptionId, subscriptionName, resourceGroup, tags = iff(isnull(tags1) or tostring(tags1) == '{}', vmssTags, tags1), properties = properties1, resources = resources1
| order by id asc

InScope = (Subscription in SYNC_SUBSCRIPTION_IDS OR Subscription in SYNC_MANAGEMENT_GROUP_IDS)
          AND (SYNC_RESOURCE_GROUP_NAMES is empty OR ResourceGroup in SYNC_RESOURCE_GROUP_NAMES)

Per-Account Active / Passive Entra ID Group Routing (AWS, GCP & Azure)

Default group names follow dfs-<cloud provider>-<cloud account>-<os>-<mde mode>, entirely lowercase. Windows and Linux have separate groups for each AWS Account, GCP Project, or Azure Subscription, with a hyphen between OS and mode: windows-passive, windows-active, linux-passive, or linux-active. Global setting SYNC_DEFAULT_GROUP_MODE defaults to Passive (can be set to Active). If a device is already a member of its counterpart group, it is not added to the default group. AWS and GCP machines are strictly excluded from Azure Subscription groups. Existing custom literal prefixes retain their legacy formatting. Changing the configured templates does not rename old groups or migrate/remove existing memberships:

Troubleshooting, KQL trace queries & common status remediation

Every execution of ScheduledInventory, EventTrigger, and MachineWorker writes structured operational traces to Application Insights and persists its full PowerShell execution transcript in the ScriptOutput column of log_ rows (viewable inline under 04 Function App & logs → View script output).

1. Application Insights — All Sync Transcript & Worker Traces

Run in Application Insights → Monitoring → Logs to view all PowerShell output, queries, and correlation decisions:

traces
| where timestamp > ago(24h)
| where message startswith "[ScheduledInventory]"
     or message startswith "[EventTrigger]"
     or message startswith "[MachineWorker]"
     or operation_Name in ("ScheduledInventory", "EventTrigger", "MachineWorker", "Dashboard")
| project timestamp, operation_Name, severityLevel, message
| order by timestamp desc

2. Application Insights — ARG & MDE Queries + Row Counts

Filter specifically to the executed Azure Resource Graph and Defender Hunting queries and how many rows each returned:

traces
| where timestamp > ago(24h)
| where message has_any ("ARG query:", "ARG page returned", "MDE query", "MDE DeviceInfo rows", "Completed:")
| project timestamp, operation_Name, message
| order by timestamp desc

3. Application Insights — Warnings, Errors & Exceptions

Surface any failed Graph/ARM calls, permission errors, or unhandled worker exceptions:

union traces, exceptions
| where timestamp > ago(24h)
| where severityLevel >= 2 or itemType == "exception"
| project timestamp, itemType, operation_Name, severityLevel, message, outerMessage, details
| order by timestamp desc

4. Log Analytics Workspace — Equivalent AppTraces Query

Run in the backing Log Analytics Workspace → Logs blade (uses AppTraces / TimeGenerated schema):

AppTraces
| where TimeGenerated > ago(24h)
| where Message startswith "[ScheduledInventory]"
     or Message startswith "[EventTrigger]"
     or Message startswith "[MachineWorker]"
     or OperationName in ("ScheduledInventory", "EventTrigger", "MachineWorker", "Dashboard")
| project TimeGenerated, OperationName, SeverityLevel, Message
| order by TimeGenerated desc

Common Status Codes, Compliance Flags & Remediation Guide

Symptom / Status Root Cause Resolution
InventorySync discovers 0 machines The Worker Function App's System-Assigned Managed Identity lacks the Azure Reader role on the target Subscription(s) (SYNC_SUBSCRIPTION_IDS) or Management Group(s) (SYNC_MANAGEMENT_GROUP_IDS), or SYNC_RESOURCE_GROUP_NAMES filters them out. Assign Azure Reader to the Worker Managed Identity on every target Subscription or Management Group. Without Reader, Azure Resource Graph silently returns 0 rows.
NoMdeMatch No onboarded MDE DeviceInfo row matched the Azure Resource ID (MdeAzureVmId) or vmId (LoggedOnUsers / DeviceName) within the 30-day lookback window. Verify the MDE.Windows or MDE.Linux extension is installed and provisioned on the machine and that OnboardingStatus == 'Onboarded' in Defender for Endpoint.
StaleMde The server matched an MDE record, but its latest DeviceInfo.Timestamp is older than SYNC_FRESHNESS_HOURS (default 24 hours). Check the MDE sensor health on the endpoint (MdeSensorHealth) or increase SYNC_FRESHNESS_HOURS (up to 168 hours).
AmbiguousMde Multiple distinct MDE DeviceId records matched the same server within the freshness window. Group changes are paused by design (Add-Only fail-closed safety) until duplicate MDE records age out past SYNC_FRESHNESS_HOURS or are offboarded/merged in Defender XDR.
NoEntraDevice MDE DeviceInfo matched the server, but AadDeviceId is empty. Ensure the server is Microsoft Entra joined / hybrid joined (or Arc-enabled server Entra identity is registered with MDE) so MDE reports AadDeviceId.
EntraDeviceNotFound MDE reported an AadDeviceId, but GET /v1.0/devices?$filter=deviceId eq '{AadDeviceId}' returned no device object in Entra ID. Verify the device object has not been deleted in Microsoft Entra ID and belongs to the same Entra tenant.
EntraDeviceDisabled The correlated Microsoft Entra device object has accountEnabled == false. Re-enable the device in Microsoft Entra ID if the server is active; disabled devices are never added to security groups.
MissingIdentifier Missing cloud account/project identifier required to build the target group name (AccountId tag for AWS Arc machines, ProjectId tag for GCP Arc machines, or Subscription displayName for Azure machines). Tag AWS Arc machines with AccountId=<12-digit-account-id>, tag GCP Arc machines with ProjectId=<gcp-project-id>, and ensure the Worker Managed Identity has Reader on the Azure Subscription.
GroupNotFound The target Entra ID security group <Prefix>{Passive|Active}-<Identifier> does not exist in Entra ID, and automatic group creation is not enabled. Start sync 403 / non-JSON response Easy Auth may reject browser POSTs before they reach the function when a no-referrer policy suppresses the referrer header. Start sync disabled / not configured (503) The report Service Bus namespace setting is missing.
